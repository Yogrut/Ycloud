# 后台配置参数边界审查

审查日期：2026-10-13。范围为管理员后台可编辑配置、对应 API、持久模型校验和前端输入转换；不是 VPS 性能压测，也不涵盖管理员手工填写所有启动环境变量的错误。

## 校验链路

后台修改经管理员认证、CSRF 检查和 64 KiB 正文限制后执行。`AppState::update_config` 修改候选配置，再调用 `ConfigFile::validate`，验证成功才落盘并发布内存；存储配置的发布流程也校验完整候选。前端输入范围只是交互提示，不替代服务端校验。

结论：已检查的主要数值配置都有服务端范围或类型校验，未发现只能靠前端阻止越界保存的缺口。部分字符串、起始日期边界由服务端最终检查，前端不一定提前限制；这不是授权或落盘校验绕过。没有为布尔开关、合法的不限额选项额外增加上限。

## 数值和数量边界

| 参数 | 默认值 | 当前服务端范围及语义 |
| --- | --- | --- |
| 网页文件上传并发 | 4 | 1–32，每网页队列；S3 每账号活动文件准入使用同一设置，跨页面、跨存储共享，全站仍最多 32 个 |
| 单文件上传 | 5 GiB | 至少 1 MiB；不超过部署 `MAX_UPLOAD_BYTES`，部署默认 100 GiB；格式硬上限 4 PiB |
| 单批上传总量 | 20 GiB | 不小于单文件上限；不超过部署 `MAX_UPLOAD_BATCH_BYTES`，部署默认 100 GiB；格式硬上限 4 PiB |
| 单批文件数 | 1,000 | 1 至部署上限；部署默认和格式硬上限均为 10,000 |
| 打包源文件总量 | 3 GiB | 至少 1 MiB；部署默认上限 100 GiB；格式硬上限 4 PiB |
| 打包条目数 | 1,000 | 1 至部署上限；部署默认 100,000，格式硬上限 1,000,000 |
| 全局上传／下载速率 | 0 | 0 为不限速，否则 64 KiB/s–1 GiB/s；不直接限制浏览器到 S3 的直传正文 |
| 存储逻辑容量 | 不设上限 | 有限值为 1 MiB–4 PiB；界面空值／0 转为不设逻辑上限，不保证实际磁盘容量 |
| 全站、访客、普通用户及账号流量额度 | 未启用／0 | 非负整数字节，最大 9,007,199,254,740,991；方向额度 0 为不限额 |
| 流量重置周期 | 每 1 月 | 间隔 1–120 小时／天／月；锚点 2000-01-01 至 2100-01-01 UTC，时区偏移 -840 至 840 分钟 |
| 管理员／首页登录失败次数 | 3／5 | 分别 3–10／3–20 |
| 登录封禁时间 | 60 分钟 | 5 分钟–24 小时；后端按秒保存，前端显式编辑按整分钟 |
| 日志保留天数 | 7 | 只能为 1、3、5、7、15、30 |
| 日志保留条目 | 5,000 | 500–20,000 |
| 存储／普通账号／WebDAV 挂载／文件夹锁数量 | 首次安装未配置 | 分别最多 16／100／1,000／10,000；用户权限必须引用现有存储且不能重复 |

部署上限、程序格式上限和实际可承受负载是三件事。调大配置不会增加 CPU 核数、磁盘速度或带宽；后端 I/O、管理写入、全局及保留直传会话、S3 分片预算不变，S3 每账号活动文件上限与配置同步。

S3 单对象还受提供商及 Multipart 格式限制；4 PiB 是配置数字格式边界，不表示所有后端都能上传 4 PiB 单文件。当前默认 100 GiB 部署上传包络低于 Multipart 的分片格式容量，不能用调大参数保证远端服务支持更大对象。

## 字符串、枚举和关联规则

- 管理员、普通用户和 WebDAV 用户名最多 128 个字符；普通用户名禁止空白且须唯一。存储名最多 64 个字符，WebDAV 挂载名最多 128 个 UTF-8 字节。
- 管理员、普通用户和 WebDAV 新密码至少 12 个字符；网页门禁和文件夹锁新密码至少 8 个字符。最大均为 1,024 个字符且不超过 4,096 UTF-8 字节。可选密码的留空／移除规则按各接口原语义处理。
- S3 Endpoint 最多 2,048 字节，Bucket 为 3–63 位 DNS 兼容名字，Region 最多 64 字节，Prefix 最多 1,024 字节，Access Key ID／Secret Key 分别最多 256／4,096 字节；提供商、寻址方式和路径格式由服务端检查。
- 绑定 URL 最多 300 字节且必须为 HTTPS 域名；主机最多 253 字节、单标签最多 63 字节、可信代理 IP 最多 16 个；端口和 IP 类型明确校验。
- 开关和周期单位通过布尔／枚举类型约束。访客下载依赖访客访问，账号写权限依赖浏览权限，存储引用须有效；WebDAV 与文件夹锁范围不能重叠。TOTP 秘密、验证码和恢复码沿原验证规则，最多保留 10 个恢复码哈希。

## 本次发现并处理的一致性问题

原固定四文件 worker 与 S3 每账号四活动文件准入会让较大设置产生可避免的拒绝。两处现在直接读取同一个持久配置，准备／状态接口不再把直传值截到 4，也不保留第二个账号上限字段；没有用失败重试消化冲突。降低设置时已有文件继续完成，新直传按当前值准入。版本 17 在原迁移链中为旧配置补默认 4，保留其他配置。

混合存储恢复时，各存储使用同一配置；如果准备期间配置变化，一轮 worker 池仍采用该轮回执共同允许的有效并发，不让最后返回的较大值覆盖较小值；下一轮重新计算。已用两种存储顺序及提高下一轮并发的行为测试复核。直传准入测试另覆盖 1／4／8／32、账号共享、全局 32／保留 128 上限及降低设置不取消已有文件。
