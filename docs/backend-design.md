# 后台设计与维护

最后核对：2026-09-27。本文描述当前代码，不是未来功能承诺。

## 控制原则

- 管理接口在服务器验证管理员身份和 CSRF，不能只隐藏入口。管理员新登录替换旧会话；认证失败不会退出旧会话。
- 管理员调整存储可以取消未完成上传，不要求用户先停止。正式提交成功的文件保留；取消清理只处理该任务的临时数据。
- 简化用户操作，不删除用于原子提交、临时文件归属、容量核算和恢复的必要标识。
- S3 直传由浏览器与对象存储交换文件；中转仅供客户端不能直连时使用，不按内网/公网区分。

## 配置发布与存储切换

`state.rs` 将远程准备与配置发布分开。存储设置使用非排队准入，同一时刻已有存储设置操作时返回冲突；连接准备最多 60 秒。准备失败不发布新配置，也不先中断旧任务。

启动时启用存储逐条初始化，共用 60 秒总截止时间，不是每个存储各等待 60 秒。时间用完后其余实例标为不可用，服务仍启动；失败不会无限循环初始化，管理员可在后台重试。初始化不清空桶，只测试连接并恢复经过归属认证的 Ycloud 事务；没有归属证据的对象保留。

需要中断时取消旧传输、关闭新操作准入，等待已进入提交边界的操作；此阶段总等待上限 5 秒。超时返回明确冲突，本次配置不修改。超时并不意味着正式提交被回滚，也不保证旧上传未受到取消信号影响。

全局配置发布锁的获取等待上限为 5 秒。保存存储时只合并存储相关字段到最新配置，保留期间已保存的账号、传输限制等其他设置。磁盘写入成功后发布内存，必要的配置提交在 HTTP 客户端断连后继续完成。管理员写请求最多 4 个同时执行，超出直接拒绝，不无限排队。原子写入仍需操作系统磁盘完成；5 秒不是强制中断已开始磁盘提交的保证。

改名、权限、容量变化复用现有实例；更换连接、停用、删除或切换上传方式取消旧传输。新连接初始化及事务恢复不占用全局配置锁；登录日志压缩只在保留策略变化时后台执行，不附带在每次配置保存上。

传输和登录保护编辑只发送改变的字段。用户、存储、WebDAV、文件夹锁编辑携带不透明版本标记，服务器在相关更新锁内检查；该条配置变化时拒绝旧表单。标记采用进程内随机密钥 HMAC，不返回敏感值；重启使旧表单失效。标记是管理 API 字段，不修改磁盘配置版本。旧客户端不发送标记时仍兼容，但不具备旧表单冲突保护。

## 结果与恢复

配置和登录保护状态共用私有文件原子发布边界：发布前失败不更新内存；发布后备份刷新或目录同步失败记录警告，不虚假宣称配置未保存。登录限制先持久化候选再更新内存；事件日志追加失败不否认已经生效的限制。

管理员可核实的设置写入失去响应时，前端安全读回当前状态，不重新发送写请求。额度、登录保护、传输限制以及部分实体修改/删除可以读回确认；新建操作和隐藏密码不能仅凭列表推断成功。网络仍不可达或无法证明时保留未确认反馈，不伪报成功。此机制不是新的任务队列。

上传使用现有提交/清理状态和任务标记自动确认。完成文件保留；未完成临时数据及 Multipart 分片自动回收。存储修改或移除时，未结清的任务在进程中保留原后端引用，恢复按后端实例分组，不会拿相同存储 ID 的新连接去处理旧任务。未结清责任不随普通批次 TTL 淘汰；结清后释放旧后端。

移除或改变 S3 连接前，原连接先加密写入配置目录下 `.ycloud-system/retired-storage.enc`，确认持久化后才发布新配置。记录最多 64 条、文件最大 1 MiB，不对外返回凭据。独立后台任务每 60 秒轮转尝试一条，单次最多 30 秒；网络不可达时保留记录供下次及重启后处理。只恢复原连接里可证明归属的事务，不清空桶；无归属孤立对象保留。进程内使用原后端的门禁，已配置同一命名空间时使用当前后端门禁；旧命名空间清理未结束前不允许独立重新添加，以免把新任务当作遗留任务。清理完成后原凭据随记录删除，原配置主密钥必须保留。

S3 文件和空目录删除成功必须确认对应对象不存在，不能只信 DELETE 的 HTTP 状态。正式上传发布后核验对象，再返回成功；成功不取决于临时垃圾清理。临时清理同步尝试最多 500 ms，其余由已有持久事务恢复；管理员取消、且尚未进入正式发布的上传直接退出传输，不等待远程 HEAD/Abort 清理。提交后核验无法完成时返回未确认结果，不伪报普通失败，也不自动重复写入。

上传、单文件移动和目录变更共用正式提交后的收尾策略。目标及源删除确认完成后，最终阶段记录写入、临时垃圾和事务记录清理同步尝试最多 500 ms，失败或超时不否认已验证的正式结果；已有认证记录让后台继续核对。目录在复制和删除过程中按批次记录进度，最后一次进度合并到最终阶段记录，避免正式变更已经完成却被多余记录写入报成失败。恢复模式仍严格等待并确认清理，不能因前台成功就清空待处理责任。目录部分变更后某一步失败，整体结果标为未确认，不把单对象的未删除扩大成整个目录未变更。

批量 API 的 `success` 统计已确认提交项（包括待收尾），`pending` 统计结果未确认项，`failed` 只统计确定失败项；总项数为三者之和。逐项的 `operation` 仍标明提交/清理状态；网页兼容旧响应，按逐项结果分别展示成功、已提交待收尾、待确认及失败，未确认项不因 `failed=0` 被隐藏或报告全部成功。

仍有边界：上传批次网页结果及部分管理操作回执尚未跨重启持久化，新建/密码修改不能仅靠列表证明；当前自动恢复保留的是存储事务和旧连接清理责任，不应称为所有操作结果完整闭环。后台修改仍最多等待 5 秒取得存储排他边界；已经进入正式提交、以及占用同一门禁的恢复工作尚未全部拆成短提交/后台清理，不能保证任何时候都立即保存。单文件删除尚无跨重启持久结果回执；本次移动/目录/批量结果维护也不代表所有文件操作及所有外部修改组合已完成部署验收。

## 登录与权限

管理员密码/TOTP 改动只撤销管理员会话。普通用户额度变动不撤销登录；密码、用户名、启用状态或存储权限实际变化才撤销对应用户。服务器文件权限校验仍独立执行，不能因为浏览器显示旧界面而放行。

## 状态、内存与流量

存储左侧绿色表示最近连接操作成功，红色表示连接检查失败/后端未准备。读取、传输和变更结果可更新缓存；非法路径、额度及用户权限错误不等价于存储断连。健康任务独立于清理任务，每 300 秒检查已缓存实例，单次最多 10 秒；管理存储页可见时每 300 秒读回状态，不在展示接口里高频探测。灯不是磁盘健康诊断或实时 SLA，停用另行标注；启动时未准备成功的实例需重新启用/编辑初始化。

S3 直传为 4 分片并发、基础 64 MiB，载荷不经过 VPS。中转使用流式转发和进程全局载荷字节预算：可检测内存上限的 1/32，限制在 4–32 MiB，检测失败默认 16 MiB；不是整个进程 RSS 硬上限，TLS/SDK/其他工作仍占内存。

Ycloud 统计/限制的是经过 VPS 的文件字节，不是物理网卡总流量。直连上传与下载不计入管理员、普通用户、访客及全站用量。仅修改额度不改变原重置时间戳或时区。

仪表盘显示“总下载”“总上传”，简短说明为“仅统计Ycloud的文件传输”；这是显示文案调整，不扩大统计范围，S3 直连仍不计量。

流量逐帧持久记账仍保留硬额度和重启重放保证。先运行 `cargo test durable_frame_accounting_baseline --locked -- --ignored --nocapture` 测量，再决定是否需要合并持久化；不能为提速无说明地放宽额度或丢失崩溃前记账。

2026-09-27 Windows 本机 debug 基线：1024 次 64 KiB 持久记账耗时约 632 ms，纯记账吞吐上限约 101 MiB/s。这不是端到端上传测速，也不能推断 NAS/VPS 磁盘性能；本轮未引入改变持久化语义的聚合记账重构，真实部署若证明瓶颈明显再评估。

## 维护与验证

更改 API 字段、默认值、提交/取消语义、流量口径、目录或部署方式时，同步维护 README、本文及相应测试；记录“实际完成”“未验证”“仍有边界”，不要累积互相矛盾的方案文档。

提交前运行：`cargo fmt --all -- --check`、`cargo clippy --all-targets --all-features --locked -- -D warnings`、`cargo test --all-targets --locked` 和 `frontend/` 下 `npm run check`。前端构建更新 `static/app/`，后端将其嵌入二进制。Windows 单元测试不替代 NAS/Linux 容器、真实 RustFS 网络及低内存并发验收。

本轮 Windows 验证：Rust 303 项通过、4 项手动测试跳过；fmt、全部 features 的 Clippy 通过。前端 305 项通过，ESLint、TypeScript 与生产构建通过；构建仍提示主 JS 大于 500 kB，未掩盖警告。本次增加已确认移动不等待慢清理、目录删除临时对象变化时前台成功但恢复责任不结清、事务部分失败不允许整体重试、批量分类及仪表盘文案回归。未执行真实 NAS/RustFS 或 Linux 断电验收；流量性能改造按用户要求不在本轮范围内。
