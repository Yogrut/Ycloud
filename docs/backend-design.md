# 后台设计与维护

最后核对：2026-10-07。本文描述当前代码，不是未来功能承诺。

README 面向项目使用与部署，保留主要功能及必要注意事项；本文维护内部实现、提交边界和恢复规则。改动时按职责同步对应文档与回归测试，不将每次维护细节追加到 README；`Temporary/` 中的审查草稿不能代替版本化设计文档。

## 控制原则

- 管理接口在服务器验证管理员身份和 CSRF，不能只隐藏入口。管理员新登录替换旧会话；认证失败不会退出旧会话。
- 管理员调整存储可以取消未完成上传，不要求用户先停止。正式提交成功的文件保留；取消清理只处理该任务的临时数据。
- 简化用户操作，不删除用于原子提交、临时文件归属、容量核算和恢复的必要标识。
- S3 直传由浏览器与对象存储交换文件；中转仅供客户端不能直连时使用，不按内网/公网区分。

`auth.rs` 维护 HTTP 登录流程和请求授权；`auth/login.rs` 定义登录凭据快照和签发前的复核规则；`auth/session.rs` 维护有界会话及作用域令牌；`auth/password.rs` 维护密码计算和两步验证证明。浏览器登录与 WebDAV 共用密码输入长度校验；管理员新登录替换旧会话，用户及文件夹令牌仍按各自归属撤销。密码任务持有并发许可直至计算结束，HTTP 等待者取消不会提前释放许可。

账号登录先按入口捕获具名凭据快照，不为普通用户复制管理员两步验证秘密。耗时验证完成后，在凭据变更共用的 `auth_transitions` 锁内核对账号身份、密码和相关二次证明，再消费证明并签发会话；失效的旧快照不能在撤销后重新建立会话。失败分支共用持久失败记录和响应，不用空用户 ID 兜底。网页登录密码及限制策略来自同一次配置读取；`me` 的账号名称、启用状态及访问密码要求也共用一份配置快照，不宣称整个响应跨会话与配置为原子观察。

管理员和普通用户会话仍为登录时起固定 24 小时，首页/文件夹通行凭据仍为 7 天，不因访问续期。持久 Cookie 可跨浏览器关闭和电脑重启保留，保存的是随机令牌，不是明文密码；服务器重启后原内存会话失效。本次不调整登录时长或增加“记住登录”选项。

`security.rs` 在统一请求边界选择客户端 IP，登录日志、失败限制及封禁共用这一地址。“域名绑定”访问地址下的“可信代理 IP”随绑定一起持久保存，确认后立即生效，不需要环境变量或重启。只接受名单中精确 TCP 连接方的单个有效 `X-Real-IP`；最多 16 个 IPv4/IPv6，保存时归一 IPv4-mapped IPv6、排序去重，清空名单关闭转发头信任，解除域名同时清除名单。默认空名单，未信任连接的转发头一律忽略，已信任代理不提供该头时保留直连地址，重复或非法值返回 400。代理须覆盖而不是追加此头；不解析任意转发链、不根据私网地址或 HTTPS 域名自动信任，不读取 `X-Forwarded-For` / `Forwarded`。配置版本 16 保留原域名并将旧版本废弃的代理字段初始化为空，避免静默复活；新版本明确保存的名单跨重启保留。旧日志保持原样，历史上错误绑定代理 IP 的封禁须由管理员核对处理，不自动清空安全记录。

后台同一页内的普通导航用 History API 更新当前设置页，保留后台壳和已加载配置；每次切换仍在后台重新读取配置和校验授权，401/403 显示登录，不用网页缓存绕过认证。支持浏览器前进/后退、直接深链和刷新；带修饰键或非左键的点击保留原链接行为，离开后台仍按原整页生命周期交接。存储页的五分钟定时读取只在该页激活且可见时执行，卸载解除监听和计时器；页面专属读取/草稿仍随子页面卸载。初次进入、页面 API 及跨入口导航仍有网络等待，本次不引入 SSR、通用路由框架或离线配置缓存。

嵌入的 HTML、JS、CSS 和 favicon 使用内容 SHA-256 ETag，进程内每资源只计算一次；GET/HEAD 的匹配条件请求返回无正文的 304，内容变化返回新内容。固定资源 URL 保持 `Cache-Control: no-cache`，每次使用须重新验证，不改成 immutable 长缓存；HTML 也不缓存账号或配置。API、文件内容和认证策略不受该缓存变更影响。NPM/CDN 可改变条件请求传递，真实跨境加载耗时仍需部署验收。

登录入口保持同步；文件页、独立预览页、后台壳及后台各设置页经 Vue 异步组件按需加载，不引入路由依赖、SSR 或第二份配置缓存。`shared/lazyPage.ts` 只共用页面代码的加载/错误策略：立即显示加载提示，代码等待 30 秒仍未完成则提示错误；该期限不取消文件传输或 API。模块成功加载后在当前文档内复用，不保留已卸载页面的实例或敏感草稿。失败只提供手动刷新并提示未完成操作，不自动刷新、重发业务写入或无限重试。首次进入某页仍有网络等待，后续后台导航仍重新验证授权/配置；入口体积下降不等于真实香港弱网耗时已经验收。

Vite 保留固定入口 `app.js` 和单份完整 `app.css`，延迟 JS 分包使用内容 hash 文件名，避免在一次页面运行中混入不同版本的分包。构建时 `build/embeddedAssets.ts` 根据实际输出生成 `static/app/embedded-assets.rs`，只接纳当前平铺的 JS/CSS 名称，重复、未支持类型或缺少入口则构建失败；新增图片/字体等资产类型须先明确扩展构建清单及 MIME 规则。Rust `app/frontend_assets.rs` 编译嵌入这份有序清单，通过白名单查找资源并沿用每资源 ETag 和 `no-cache`，不读取请求指定的磁盘文件，不将缺失分包回退为 HTML。清单引用的文件缺失会使 Rust 编译失败，新增分包不必手写后端路由；CI 也检查构建新增的未跟踪产物，避免只检查旧文件 diff。

发布必须携带完整 `static/app/`（包括生成清单），现有 Docker 的整体复制方式保持可用，不新增运行时资源目录或环境变量。已打开的旧页面在重新部署后请求旧 hash 分包可能得到 404，应在确认没有未完成操作后手动刷新；服务不保留所有历史分包，也不通过自动刷新丢弃页面任务。历史维护记录中的“大于 500 kB”是当时构建事实，不代表本轮产物。

## 配置发布与存储切换

配置模型集中定义初始设置；首次启动传入独立生成的管理员及访问密码哈希，再依据部署限制收窄传输上限。`config/credentials.rs` 集中转换 S3 和 TOTP 凭据，每次转换只读取一次配置密钥；明文候选的只读解码不创建密钥。加载和保存编排位于 `persistence.rs`，原子文件发布及备份路径规则位于 `commit.rs`，发布层不反向依赖加载层。存储身份、提供商及字段仍参与密文绑定，旧编码迁移和完整候选校验先于发布。

`state.rs` 将远程准备与配置发布分开。存储设置使用非排队准入，同一时刻已有存储设置操作时返回冲突；连接准备采用 60 秒安全退出预算，不用整段 timeout 丢弃正式写入。更换连接先中断并排空旧实例，再准备候选；候选准备或发布失败保留原配置，旧准入只在原执行者退出后恢复，旧传输不会复活。新建候选不影响其他实例。

本地/S3 编辑的共同生命周期在 `state/storage_update.rs`：小型纯决策区分不变、重新启用、策略中断和连接替换，票据失效单独保留，避免重新启用同时收紧权限时漏掉失效。两种编辑共用取得原门禁、准备候选、保留旧清理责任并保存、失效票据、退役及发布的顺序；编辑 guard 一直保留到发布结束。连接身份只排除在线容量策略和 S3 中转开关，其他 S3 字段仍全部参与比较；没有缓存实例时不能宣称复用。路径/挂载及凭据回填仍归各自入口，候选初始化、本地恢复、S3 恢复及旧连接清理仍由原实现承担。初始化或保存错误不退役原实例、不发布新额度，也不恢复已经取消的旧请求；这不是新的事务框架或统一操作回执。

启动时启用存储逐条初始化，共用 60 秒准入/安全退出截止时间，不是每个存储各等待 60 秒。到期不启动下一实例，其余标为不可用，失败不无限循环初始化，管理员可在后台重试。已发出的 S3 正式写入等待现有 SDK 调用返回，本地已进入的发布与恢复不从外部丢弃；SDK 请求、文件系统同步可能使实际等待超过预算，这不是操作系统 I/O 的硬时间保证。初始化不清空桶，只测试连接并恢复经过归属认证的 Ycloud 事务；没有归属证据的对象保留。就绪实例使用未绑定初始化截止时间的原客户端，不能在 60 秒后自己失效。

运行时注册表区分就绪、停用、不可用：只有就绪且不在中断结算中的实例接收新文件请求；停用实例仍保留原后端供状态读取与必要维护，不可用项不持有可缓存后端。后台沿用现有 `pending` 状态展示“处理中”，连接灯仍显示最近的缓存连接结果；配置已保存不等于实例已能服务。停用优先显示“已停用”，状态切换不把不可用项伪装成已初始化连接。

停用、删除、收紧访客访问/下载权限和切换中转模式先关闭准入、取消旧传输，再发布设置；不等待整项文件变更或垃圾清理。未排空的 `StorageEditGuard` 把门禁交给该实例唯一的后台结算执行者，重复停用不启动另一条结算。重新启用先检查旧执行者、恢复/容量门禁及待恢复日志；未到安全边界则拒绝并保留停用配置，不自动替管理员打开。更换连接/挂载路径仍须排空原实例，以保护同一命名空间及容量账本身份；最多等待 5 秒，超时明确冲突、本次配置不修改。即使同时勾选停用，连接变更也不能跳过这一边界。

管理员中断同时暂停 S3 请求准入和可取消的只读工作，包括目录/容量扫描、恢复清单及事务读取、HEAD 核对；仅内部临时命名空间的删除和 Multipart Abort 可被中断，持久记录保留供以后自动处理。`s3_backend/maintenance.rs` 在长操作开始时冻结取消代次、可选停止标记和截止时间，嵌套工作继承原代次且只能收窄时限。正式 PUT/COPY/DELETE 和已发阶段日志写入不直接丢弃；到期后在下一次读取/请求准入退出。恢复后台请求能力不会复活旧工作。结算执行者保留旧门禁直到文件所有者、S3 恢复和容量门禁全部排空；退役后端仍禁止用户准入，但允许原连接继续承担清理责任。

旧连接清理及未知上传清理仍由既有串行 worker 执行，每实例一轮采用 30 秒安全退出预算；一个慢实例不消耗其他实例下一轮的全部预算。关闭信号到达时先取消可取消阶段，再等待在途正式写入返回，不直接丢掉整轮恢复 future；不因此新增并行恢复或任务框架。目录完成阶段日志先单独等待写入，再进入最多 500 ms 的临时垃圾收尾；已证明正式完成后日志/清理错误不重新标为未提交。完整本地恢复仍有原条目与清理预算，但不承诺整体固定耗时。

全局配置发布锁的获取等待上限为 5 秒。保存存储时只合并存储相关字段到最新配置，保留期间已保存的账号、传输限制等其他设置。磁盘写入成功后发布内存，必要的配置提交在 HTTP 客户端断连后继续完成。管理员写请求最多 4 个同时执行，超出直接拒绝，不无限排队。原子写入仍需操作系统磁盘完成；5 秒不是强制中断已开始磁盘提交的保证。

改名、权限、容量变化复用现有实例；纯改名/容量及放宽访客策略不中断，收紧访客策略会取消旧传输。更换连接、停用、删除或切换上传方式也取消旧传输。新连接初始化及事务恢复不占用全局配置锁；登录日志压缩只在保留策略变化时后台执行，不附带在每次配置保存上。

上传选名开始时记录进程内存储切换代次；建立票据时若管理员已切换或停用存储，拒绝旧计划并要求重新准备。代次检查与旧票据失效共用批次锁，不让管理员等待目录扫描。

上传票据的持久状态变更按票据串行，不再持有全局批次表锁等待磁盘。新票据先在表中保留名额与路径，再由独立创建者发布清单；清单成功且存储切换代次未变化才返回票据。慢写入不会阻塞其他批次的开始、结束或状态读取，正在结算的票据不会被过期/压力回收。同一票据内仍先持久化后发布内存状态；管理员失效待开始项不等待票据写盘，开始项写盘返回后再次检查取消，不能复活旧上传。持久索引格式和原有账号/全局预算不变。

传输和登录保护编辑只发送改变的字段。用户、存储、WebDAV、文件夹锁编辑携带不透明版本标记，服务器在相关更新锁内检查；该条配置变化时拒绝旧表单。标记采用进程内随机密钥 HMAC，不返回敏感值；重启使旧表单失效。标记是管理 API 字段，不修改磁盘配置版本。旧客户端不发送标记时仍兼容，但不具备旧表单冲突保护。

后台存储页面的表单默认值、编辑回填、供应商寻址默认值、容量校验和 S3 请求字段转换集中在 `apps/admin/useStorageForm.ts`；`StorageView.vue` 保留连接测试、请求版本、新建后启用及保存/删除编排。编辑回填清空凭据输入，留空保留现有密钥；只修剪连接字段，不修剪密钥。关闭访客访问同时关闭访客下载。连接测试期间修改表单后，迟到结果不覆盖当前反馈；没有改变管理请求和服务器配置发布规则。

用户编辑的权限草稿、权限联动及新建/差异请求转换在 `apps/admin/userAccountForm.ts`；`UsersView.vue` 保留流量读取、界面和请求编排。差异比较按具名字段进行，不依赖 JSON 对象插入顺序；存储数组顺序保持，不把它改成无序集合。请求复制权限和额度，不复用可继续编辑的草稿对象。密码留空不提交，替换密码原样发送，用户名单独修剪；版本标记及缺省额度写入保持。用户额度和共享额度编辑共用 `trafficQuota.ts` 的默认值、比较和非负安全整数字节校验，格式展示仍按各页面用途维护。

WebDAV 和文件夹锁的路径输入格式及请求差异在 `apps/admin/storageAccessForm.ts`；编辑按钮和保存请求共用同一份差异结果，页面添加原版本标记并负责验证、网络请求和反馈。路径格式只统一分隔符，不解析 URL、点段或修剪文件名空白，不能代替后端路径安全和范围校验。WebDAV 更新的空密码仍为显式清空，新建的空凭据仍省略；文件夹锁拒绝根目录和清空密码的规则仍留在其页面。管理员、WebDAV 与锁页面共用 `shared/passwordInput.ts` 的掩码和延迟选中行为，不合并各自的密码要求或提交语义。

传输限制的七项输入草稿、精确字节基线、部署上限校验与差异请求在 `apps/admin/useTransferLimitsForm.ts`；`LimitsView.vue` 负责编辑界面、请求、忙状态和反馈。显示用的 GiB/MiB 小数精度不是持久配置值，未编辑的大小和限速沿用服务器原始字节值，不能因为修改其他字段而四舍五入并再次提交。回填、重置和成功后的显示使用同一映射，草稿与基线独立；模块不访问网络，不读取账号或认证信息，不新增通用表单框架。服务端限制、旧响应缺省值与管理客户端的结果确认策略保持。

登录保护的回填、四字段差异及输入校验在 `apps/admin/loginProtectionForm.ts`，不依赖 Vue 或网络；`ProtectionView.vue` 管理响应式草稿、界面与保存反馈。按钮是否有变化与保存请求共用同一字段比较，输入控件与校验共用限制常量。后端允许按秒设置封禁时间，未编辑的时长保持原秒数，不强制转成整分钟或阻止修改错误次数；显式编辑时仍要求 5–1440 整分钟。此模块不处理访问日志保留策略，也不改变后端登录限制和授权。

访问日志的筛选、已应用搜索、分页、最新查询及定时刷新在 `apps/admin/useSecurityLogs.ts`；`SecurityView.vue` 保留显示、清空/封禁确认及保存策略操作。查询复用管理客户端的取消信号和等待上限，替换查询或离开页面时取消读请求，同时以版本拒绝迟到结果；销毁后不启动写操作完成后的日志刷新。取消查询不取消已提交的管理写请求。日志策略重复保存直接退出；服务器确认保存或封禁后立即反馈并独立刷新列表，刷新失败单独展示，不延迟或否认已确认的写入，也不自动重发写请求。页大小、刷新频率、弹窗期间及非首页暂停刷新的规则保持，没有新增队列或通用查询框架。

管理员两步验证的准备、启用、停用、复制反馈及敏感草稿生命周期在 `apps/admin/useAdministratorTotp.ts`；`AccountView.vue` 保留账号凭据、网页密码移除确认、显示和重新登录提示时序，域名绑定继续由独立组件维护。两步验证三种请求共用单一忙状态，接口和各自错误反馈不泛化；密码原样发送，仅验证码/恢复码修剪。启用后清空密码、验证码和绑定密钥，但保留一次性恢复码直到用户关闭；停用确认后立即提示重新登录。关闭或卸载清除本地草稿引用，迟到结果不重新填入卸载页面；已提交的管理写入不取消、不自动重复。此清理不保证 JavaScript 内存物理擦除，不改动服务器二次验证或会话撤销规则。

管理员账号的回填、字段差异及最低密码长度校验在 `apps/admin/adminAccountForm.ts`；页面保留请求、忙状态、移除网页密码确认及反馈。按钮与提交共用差异规则，重新登录判断依据实际发送的用户名/管理员密码字段，不再另维护一套草稿比较。用户名修剪，密码原样发送；未改的掩码不提交，网页密码空字符串仍为显式移除。没有已有网页密码时，输入掩码按新密码校验，不能绕过最低长度。规则只读取用户名及网页密码是否存在，不访问网络、不合并两步验证或域名设置、不新增通用表单框架；后端仍承担最终授权和完整校验。

域名绑定的读取、保存、解除、草稿及生命周期在 `apps/admin/useDomainBinding.ts`，`DomainBindingSetting.vue` 只维护展示和反馈触发。填写 HTTPS 地址后确认保存；清空地址后确认调用现有 DELETE 接口解除绑定，不再提供独立解除按钮、二次确认页或打开域名链接。操作共用忙状态，不重复读取或排队写入；保存和解除共用已确认响应的应用规则，但保留各自接口及提示。已知配置与草稿分开，显示和回填采用服务器返回的规范化地址，不用发送的草稿推断保存成功。读取失败保留已知状态并单独报错，仍允许管理员明确保存；保存或解除失败保留草稿，不自动重发结果未知的操作。取消清除编辑状态，卸载取消读取且忽略迟到结果，不取消已提交的管理写入。后端域名校验和立即生效规则保持，不增加验证期、探测或新任务系统。

仪表盘默认展示近 7 天。今日、近 7 天、近 30 天以 `days` 参数查询，由后端依据流量周期的 `offset_minutes` 和当前时间计算账本日期；响应的 `today` 同时用于自定义日期上限。浏览器不再用自身时区生成预设查询日期，避免 UTC 与北京时间在午夜附近相差一天而被拒绝。自定义范围仍限制在保留期内、最多 31 天，`days` 不能和显式日期混用；无日期参数的旧请求仍返回当月范围。新部署没有传输时返回零用量和完整日期序列，不隐藏流量图；不迁移账本日期、不清空历史或修改既有重置周期。

后台入口的登录、配置读取、存储刷新和会话到期时序在 `apps/admin/useAdminSession.ts`；`AdminView.vue` 保留导航、页面组装和反馈展示。导航复用公共路径规范化和现有导航项，不另维护路径分支。配置读取共用管理客户端的取消信号和截止时间，替换读取或卸载时取消请求，同时拒绝迟到结果；登录与读取错误分开。存储页仍每五分钟刷新一次，页面隐藏、需要登录、正在登录或已有读取时跳过。已确认操作先反馈成功，再后台刷新，不卸载当前设置页；刷新失败独立展示，不自动重复写入。普通用户误入后台后的退出也使用有界管理客户端。卸载停止定时器、清除本地密码及验证码引用，已发送登录/退出请求不取消，也不启动卸载后的读取；不改变服务器授权、登录证明或会话撤销规则。

## 结果与恢复

网页上传同名文件按 `文件名 (编号).扩展名` 从已有最大编号继续递增，任务显示实际保存名称；WebDAV 保持客户端原有写入语义。上传队列按原始目标去重，不因服务端自动编号重复排队。管理员切换存储期间尚未完成的选名须重新准备，不将旧目录编号带到新连接。

`s3_backend/copy.rs` 集中单文件复制的准备、执行、核验及失败回滚，共用原后端的 COPY/HEAD/DELETE 请求原语；不另建复制状态系统。COPY 被接受后的读取失败（包括管理员暂停核验）、目标缺失或身份不符返回提交未知，不能作为直接重试的普通失败。校验失败仅对与 COPY 返回 ETag 匹配的目标进行条件删除，并再次确认不存在后才返回未提交、清理完成。删除子步骤的未提交不能扩大为整个复制未提交；身份已变更的对象不删除。未知结果仍触发原容量核对，但容量扫描不是这次复制的持久成功证明；本入口未新增跨重启回执或自动结果核验任务。

存储操作准入和管理员中断集中在 `storage_backend/lifecycle.rs`：生命周期租约、传输取消标记、独立写入所有者和编辑 guard 由同一职责模块维护，文件操作不再混入这些控制逻辑。现有写入预算仍为每实例 32 项，连接/挂载变更最多等待 5 秒排空；策略设置发布不等待整项操作。等待被取消或超时后，旧所有者退出之前不重新放开准入。旧请求的取消标记不随重新开放而恢复，写入任务异常仍返回提交/清理未知，不冒充失败或自动重传。`StorageEditGuard` 沿用原公开路径，事务证明、S3 门禁及实际文件处理不变。三种存储构造入口共用 `ActiveStorage::new` 初始化独立运行状态，不共用不同实例的门禁或容量，也不在构造器中隐含扫描、恢复或启动 worker。

统一接口的 S3 复制由 `copy_path` 已领取的写入所有者直接执行，不再内嵌第二层执行任务、克隆请求路径或额外保留快照失效 guard。文件和目录分支仍先估算及预留容量，再取得容量变更门禁，并由远端复制入口重新核对源大小。原 `S3CapacityAccounting` 在错误或异常退出时安排去重容量核对，删除重复的显式核对及第二层 JoinError 收尾；任务异常统一由写入所有者返回未知结果。验证复制完成后只提交一次预留并持久化账本，快照失效及准入/执行预算保留到真实工作结束，HTTP 等待者断开不取消已接受复制。本地复制仍有独立的直接调用执行边界，未机械删除；上传也有独立传输/提交责任，本轮未修改。此简化不拆分目录正式提交，不改变远端认证记录、ETag 条件、恢复或强制中断规则。

存储后台调度集中在 `storage_backend/maintenance.rs`，统一接口只保留启动与触发调用。该模块负责本地/S3 容量核对、S3 恢复的通知等待及重试，扫描、账本发布和事务恢复仍由各存储实现负责；不合并成通用任务框架。重试最小值和上限统一为 1 秒和 60 秒，恢复静默期仍为 1 秒。本地 worker 在等待及重试时不持有实例强引用，核对时仍先取得生命周期读门禁，退休实例不再扫描；容量核对领取由现有跟踪器去重。S3 worker 的单次启动、关闭通知、排他恢复及正式提交规则保持，不强制超时中断正在恢复的事务，也不据此承诺整轮清理时间预算或 S3 容量重试睡眠立即终止。

S3 运行时恢复状态在 `s3_backend/recovery_runtime.rs` 使用单锁 `RecoveryState`：待办、恢复标志、连续失败数、失败信息和重试时间一起更新及读取，不再从多个原子字段和错误锁拼接状态。重复登记仍保留首次时间；一轮成功只清除恢复标志和当前重试状态，保留历史失败信息，不批量清空待办。单条日志只有确认删除或不存在后才结清；日志不存在只表示这条恢复工作可退出，不证明文件操作成功或失败。连续失败数饱和累加。worker 单次领取、停止标志和两个 Notify 仍独立负责生命周期及唤醒，状态锁不跨网络 I/O。成功结算的调用者仍需持有排他恢复门禁，这不是新的任务状态机或提交证明；孤立对象数量由后端独立提供，也不据此保证整个后端是一次原子快照。

运行时 S3 恢复取得排他门禁后，从现有待办派生本轮快照，校验精确命名空间、日志类别及事务 ID，按原分类顺序选择一条；直接读取并复用启动恢复的单条认证/执行算法，不为每条待办扫描全部六类日志。上传事务先于内部上传意图，后者清理前还须确认同 ID 上传事务不存在；有关联事务或读取/认证失败时保留记录与临时资源。每条结束释放恢复及变更门禁，再让出调度机会；全部已登记日志结清后才执行 uploads/backups 两类只读孤立清单。后台恢复曾使容量不确定时，结清后安排一次原有容量核对，包括最后一条被前台执行者在两轮之间结清的情况。停止若发生在等待门禁期间，取得门禁后退出恢复标志，不清除责任或历史，也不发起远端工作。

上述一条限制不是总请求数或耗时保证：本轮待办快照仍遍历全部已登记键，单个目录事务仍可能涉及最多 1000 个对象，最后的两类孤立清单仍须安全分页；正式 PUT/COPY/DELETE 不被强制中断。高优先级记录持续无法判定时，仍按原失败退避阻止后续恢复，不以公平调度绕过依赖。启动、排他中断后的恢复仍做原完整命名空间检查；没有新增持久队列、配置、格式或依赖。

本地事务恢复集中在 `storage_transaction/recovery.rs`：先结算内存中的待发布记录，再只读校验完整的有界正式记录、上传/复制暂存清单及一页垃圾清单，之后执行单项替换恢复与暂存清理。读取期间按事务 ID 派生日志的锚点声明索引，避免每个锚点扫描全部日志；索引不持久化，也不能代替提交证明。未声明的日志所属锚点仍拒绝恢复，无日志的孤立锚点沿用原清理规则。正式文件身份及发布证明仍在执行时核实，清理成功后最后删日志。排他恢复期间将已校验、无活动执行者的复制暂存按原 ID 改名到垃圾区，双方目录同步；目标或完整/未完成删除记录同 ID 冲突时保留资源、拒绝猜测归属，在线 worker 不自行扫描接管复制暂存。

上传收据的启动计数与过期清理共用事务目录清单扫描；Linux 的枚举和元数据读取绑定已打开的根目录，不重新按原绝对路径寻找目录。收据使用本次操作的 32 位小写十六进制 ID，不与事务日志的 UUID 混用；先验证文件类型与名称，再处理暂存或过期记录。清单预算按 10 万条收据及每条至多一个暂存文件计算，不套用事务日志的 4096 条预算；超出扫描预算保留资源并明确报错。

每次本地恢复仅执行合计 256 个文件/目录节点的垃圾删除，不循环等整树清完；剩余垃圾及删除债务由现有在线清理 worker 继续处理。垃圾清单按现有 4096 条预算分页，避免复制交接扩大垃圾区后阻塞下一次启动；未匹配记录必须逐项确认对应垃圾实际不存在并同步目录后才可移除，不能以“不在本页”证明已删除。部分树、未处理树及对应未完成记录仍保留。预算只限制物理树删除节点，不涵盖正式替换恢复、清单读取、单文件暂存清理、复制改名和目录同步耗时；不承诺整轮恢复固定墙钟时间，也不强制超时中断正式恢复。

配置和登录保护状态共用私有文件原子发布边界：发布前失败不更新内存；发布后备份刷新或目录同步失败记录警告，不虚假宣称配置未保存。登录限制先持久化候选再更新内存；事件日志追加失败不否认已经生效的限制。

在线删除清理在 `storage/cleanup.rs` 内分开状态结算与异步调度。`CleanupState` 用一把锁维护已知债务条目和对外摘要，登记及本批完成结果同步更新，删除原两把锁之间的字节总量回写。只按本批确认完成的路径减债，不用扫描快照覆盖新登记项；失败和未完树继续保留，缺少字节记录、清单截断或扫描失败不能显示为完整统计。字节总量共用饱和求和，完成后重新计算，不从已饱和总量直接减数。服务暴露前用现有有界磁盘清单初始化债务及完整性，有遗留工作立即唤醒 worker；运行中排他恢复成功后同样通知继续清理。不为未知大小的复制暂存捏造字节数。锁不跨文件 I/O；扫描、物理删除、目录同步、256 节点预算、退避及关闭时最终清理沿用原规则，每批之后释放 I/O 和变更门禁，磁盘债务仍是持久工作依据，未新增队列或调度框架。

管理员可核实的设置写入失去响应时，前端安全读回当前状态，不重新发送写请求。额度、登录保护、传输限制以及部分实体修改/删除可以读回确认；新建操作和隐藏密码不能仅凭列表推断成功。网络仍不可达或无法证明时保留未确认反馈，不伪报成功。此机制不是新的任务队列。

上传使用现有提交/清理状态和任务标记自动确认，不提供人工核对入口。直传分片已全部传齐但最后确认命令丢失时，上传空闲超时后自动检查、提交；后台每 15 秒尝试恢复并同步任务状态，这是调度间隔，不是保证完成时间。完成文件保留；未完成临时数据及已知 ID 的 Multipart 分片自动回收；未取得 ID 的空远端会话交由桶生命周期规则回收。存储不可达时延后重试，不删除正式文件或其他任务数据。存储修改或移除时，未结清的任务在进程中保留原后端引用，恢复按后端实例分组，不会拿相同存储 ID 的新连接去处理旧任务。未结清责任不随普通批次 TTL 淘汰；结清后释放旧后端。

`upload_recovery.rs` 分开本轮后端绑定与恢复执行，不新建模块或后台队列。已有后端引用优先；未绑定项有命名空间标记时先逐项核对，没有标记的旧票据保持兼容规则。同一存储的当前命名空间只计算一次，后端也只读取一次（包括不可用结果），仅在本轮复用，下轮重新读取；不克隆整份含凭据的配置。配置读锁在计算完所需命名空间后释放，不跨后端异步查询或恢复 I/O。后续仍按后端实例身份分组并独占恢复，每组最多确认 32 项，只凭正向提交证据结清；此项数限制不等于整轮事务清理的时间或 I/O 总预算。

既有清理 worker 持有 `UploadRecovery`，只记录各后端实例下次确认的位置，不复制任务、状态或后端引用，也不持久化该顺序提示。未知项按实例、票据和路径稳定排序，每轮从上次位置环绕读取最多 32 项，同一项本轮不重复；每次实际尝试都推进位置，包括确认冲突或存储错误，避免持续未知或错误的前缀固定占用窗口。活动所有者使独占恢复失败时不推进该组。下一轮删去没有已绑定未知项的实例提示，集合缩小时归一位置；重启从头开始，不改变持久结果。稳定的待核对集合能轮到所有成员，但不承诺持续变动集合或慢存储在固定时间内全部结清；底层事务清理的有界执行仍是独立边界。

票据持久化与运行时预留由独立执行任务一并完成；该任务持有选名门禁直至建票据结束，HTTP 等待者在写盘期间断开也不会留下只有磁盘记录、运行时却没有预留的半成品，或无限积累等待中的准备任务。未收到票据响应的客户端仍需重新准备，孤立的待上传票据按保留期回收。恢复后只根据本次操作的持久凭据将未知结果确认为成功；缺少当前文件或 S3 操作标记不是“从未提交”的证明，不能自动写成失败。没有正向或明确反向证据时保留未知并继续保护原任务的恢复责任；这不改变已明确返回未提交且清理完成的失败结果。

单项上传模型与规则在 `upload_batch/item.rs`，票据主体负责认证、存储/路径/大小绑定、锁、落盘及运行时更新，`persistence.rs` 负责索引 I/O。活动额度、选名占用和保留期共用终态判断，恢复责任共用执行中/未知判断；允许取消仍仅为未开始或明确失败，不取消已完成和待核对任务。开始决定和结果分类不修改上传项，开始仍先持久化 InProgress 再改变内存。已提交优先于清理状态，未知提交或未提交但清理未完仍为 Unknown；普通成功/失败保持原规则。重启把 Pending 转为 Cancelled、InProgress 转为 Unknown，保留既知结果和操作证据，不自动重开传输。`UploadStatus` 与 `UploadBegin` 沿用原公开路径和序列化名称，未新增持久格式、状态机框架或依赖；无生产调用的布尔结算辅助入口限制在测试构建中。

票据准入在持锁期间一次派生活动批次、当前账号批次、活动项与保留项统计，不维护长期计数缓存。全局活动批次 32、单账号 4、活动项 20,000、保留批次 128、保留项 40,000 的上限保持；保留空间不足时才收集并按到期时间排列终态批次，回收最旧结果直到空间足够，再检查活动额度。运行中或未知结果不因保留空间压力淘汰；回收终态只扣减本次保留统计，不重复扫描整张表。过期移除入口同步安排原有后台索引及凭据清理，不等待或宣称远程清理已完成。

移除或改变 S3 连接前，原连接先加密写入配置目录下 `.ycloud-system/retired-storage.enc`，确认持久化后才发布新配置。记录最多 64 条、文件最大 1 MiB，不对外返回凭据。独立后台任务每 60 秒轮转尝试一条，每轮采用 30 秒安全退出预算，已发写入等待返回而不强行丢弃；网络不可达时保留记录供下次及重启后处理。只恢复原连接里可证明归属的事务，不清空桶；无归属孤立对象保留。进程内使用原后端的门禁，已配置同一命名空间时使用当前后端门禁；旧命名空间清理未结束前不允许独立重新添加，以免把新任务当作遗留任务。清理完成后原凭据随记录删除，原配置主密钥必须保留。

S3 文件和空目录删除成功必须确认对应对象不存在，不能只信 DELETE 的 HTTP 状态。正式上传发布后核验对象，再返回成功；成功不取决于临时垃圾清理。临时清理同步尝试最多 500 ms，其余由已有持久事务恢复；管理员取消、且尚未进入正式发布的上传直接退出传输，不等待远程 HEAD/Abort 清理。提交后核验无法完成时返回未确认结果，不伪报普通失败，也不自动重复写入。

共享 S3 删除算法集中在 `s3_backend/deletion.rs`：通用入口先核对当前 ETag，删除执行与不存在确认只维护一份。目录源删除、目录垃圾清理及单文件移动已经完成自身大小/ETag 核验，直接复用核验后的执行边界，避免重复同一 HEAD；普通文件、空目录及其他清理仍沿用通用入口。条件 DELETE、OSS 原有的删除前复核、管理员可暂停的临时清理与不可随意丢弃的正式删除边界保持。删除后只读取一次存在性结果：确认不存在才结清该键的恢复责任，错误响应不否认不存在证明；对象仍存在或查询错误保留原结果规则和恢复责任。单文件移动仍将删除子步骤的未提交转换为整体未知，目录正式完成后的清理仍以已提交/清理待完成反馈。本次只减少重复请求，不引入并行删除、通用事务框架或整轮时间预算。

S3 恢复记录的响应读取共用 `s3_backend/journal.rs` 的 `read_journal_payload`：声明长度先校验，ETag 必须存在，再逐块检查剩余可收集字节后追加；不先无界收集再检查。小型认证信封仍为 96 KiB，目录清单仍为 4 MiB，各自解码、认证及结构核验保持独立。无声明长度的分块响应也受实际收集上限约束，读取中断不返回半份记录；管理员只读暂停仍包围 GET 和整个读取过程，请求许可持有到读取/核验退出。共用错误文案指向恢复记录，不新增错误码或持久格式。此上限仅约束应用收集的记录内容，不是 SDK 单块、分配容量、JSON 解码及整个进程 RSS 的硬预算；不用于文件载荷，不改变写入或清理策略。

S3 上传事务与 Multipart 会话的持久模型及命名空间校验集中在 `s3_backend/transaction_record.rs`，只处理记录，不调用远端；认证日志读写、上传发布和恢复仍由各自模块负责。上传、移动和目录操作保留各自的提交证明，不合并成泛化事务。此次整理不改变记录版本或旧记录兼容规则。

单文件移动的持久模型与纯阶段/身份规则在 `s3_backend/file_move_transaction/record.rs`，执行和认证日志适配留在父模块。已复制阶段的目标快照必须与源大小一致；这是记录自洽校验，不替代远端对象核实。准备阶段才读取复制前元数据；恢复已复制阶段直接进入删除前的目标和源大小/ETag 核验，不提前重复读取随后丢弃的快照。源 DELETE 仍带原 ETag 条件，之后只做一次存在性确认：确认不存在即结清源删除，包括 DELETE 返回错误的情况；仍存在或查询失败则保持整体未知和恢复责任，不能让删除子步骤的未提交覆盖移动结果。记录版本、JSON 和认证方式保持，移动仍非原子操作。

`s3_backend/recovery.rs` 集中六类恢复日志的顺序、分类和单条分发，启动完整恢复、在线单条恢复及激活探针清理共用这些边界。原各业务模块只维护单条记录的认证、对象核验和恢复算法，不重复维护分类列举循环；共用的有界列举仍检查精确前缀、ID、分页进展及上限。内部上传意图清理前，两种恢复入口都另行 HEAD 核实同 ID 上传事务不存在；分类清单没有列出关联事务不能代替不存在证明。关联事务存在或查询错误时停止，不读取并清理意图载荷，保留责任。在线恢复仍每轮只处理一条登记日志、结束后释放门禁；启动/中断后的完整恢复仍按原顺序处理全部分类，全部完成才只读统计孤立 uploads/backups，不增加并行扫描、队列或强制写入超时。

分片上传和服务端复制共用 `s3_backend/multipart/session.rs` 的准备边界：先持久化无 ID 意图，再创建远端会话，最后持久化提供商 ID；仅全部完成后返回具名的 `StartedMultipart`，调用方才进入上传、签名或复制分片。创建结果缺少 ID 时只清理自己的意图，不根据键名猜测或枚举远端会话；ID 写入失败时按已知 ID 尝试 Abort，失败保留原记录。上传编排留在 `multipart.rs`，复制编排在 `multipart/copy.rs`，二者的完成证明和错误结果不合并；直传、中转、取消及恢复策略保持。

目录事务同样按职责分层：`s3_backend/directory_transaction.rs` 编排准备、逐对象复制/删除和恢复，子模块 `snapshot.rs` 只维护写入前的有界目录快照，`record.rs` 处理清单结构、认证和归属校验，`journal.rs` 负责远端清单读写。快照读取保留前缀检查、分页进展和页数/对象数/单对象大小限制，受管理员只读暂停控制，不发布日志或修改正式文件。测试与实现分别维护，不增加转发层或通用事务框架。目录清单沿用原有 v2 JSON 与认证字节，不改成上传的小型认证信封；1000 对象、4 MiB 清单和单对象 5 GB 上限保持。恢复清单列举复用已有的安全分页入口，不维护第二套令牌、记录数和命名空间规则；相关错误使用统一恢复记录文案。

上传暂存对象的存在性和长度检查返回原始元数据，后续 ETag 校验保持；探测错误、长度不符和对象缺失共用未提交清理入口。正式发布失败后，仅在确认目标不存在或旧对象已恢复并更新回滚记录时共用收尾；无法识别的正式对象仍保留事务，不把它当作安全回滚。

上传、单文件移动和目录变更共用正式提交后的收尾策略。目标及源删除确认完成后，已发的最终阶段记录写入等待返回；500 ms 同步收尾窗口仅用于临时垃圾和事务记录清理，不从外部丢弃阶段日志 PUT。日志写入失败或垃圾清理超时不否认已验证的正式结果，已有认证记录让后台继续核对。目录在复制和删除过程中按批次记录进度，最后一次进度合并到最终阶段记录，避免正式变更已经完成却被多余记录写入报成失败。恢复模式仍严格等待并确认清理，不能因前台成功就清空待处理责任。目录部分变更后某一步失败，整体结果标为未确认，不把单对象的未删除扩大成整个目录未变更。

三类目录操作共用一个最终阶段/清理出口，操作与完成阶段的映射由记录模块维护。阶段与逐对象进度集中校验：复制阶段不能已有源删除；复制终态仅用于复制操作，要求所有目标身份已记录且源未删除；移动/删除进入删源阶段前须记录所有目标身份，删源终态另要求所有源已确认删除。这些是持久检查点的自洽约束，不代替远端身份或不存在核验；不自洽记录停止执行并保留，不猜测修复进度。已有认证终态（复制完成或源删除完成）不再重复写入同一阶段，也不重新变更正式源/目标；删除仍逐项验证垃圾身份，最后确认日志删除才结清责任。首次终态发布失败保留旧日志，恢复读取持久证据重新核实后继续。正式操作已经确认完成时，临时删除子步骤的未提交或未知不能覆盖整体已提交结果；恢复清理错误统一标为已提交、清理待完成并禁止直接重试正式操作，原错误原因保留。上述整理不缩短长目录正式执行的门禁占用，也不新增目录操作的跨重启查询回执。

空目录的零字节 marker 同样通过统一目录事务准备、提交及清理；没有 marker 的隐式空目录继续拒绝操作。不再保留无项目调用的 `delete_empty_directory` 非事务入口。网页、批量操作和 WebDAV 的实际删除仍经统一存储接口；没有改变 HTTP 路由或递归删除规则。

批量 API 的 `success` 统计已确认提交项（包括待收尾），`pending` 统计结果未确认项，`failed` 只统计确定失败项；总项数为三者之和。逐项的 `operation` 仍标明提交/清理状态；网页兼容旧响应，按逐项结果分别展示成功、已提交待收尾、待确认及失败，未确认项不因 `failed=0` 被隐藏或报告全部成功。

网页批量反馈由 `apps/browser/operationFeedback.ts` 一次遍历逐项结果生成 `BatchReport`，摘要格式化与结果分类分开；通知颜色和详情行共用报告，不再分别依赖汇总字段或模板筛选。已提交待收尾不归入失败，未知结果使用错误提示；保留旧错误码兼容和响应顺序。新的完整成功响应清除旧报告，不让上一批详情继续显示。此报告是页面展示模型，不修改后端证据、自动重试或持久化格式。

网页删除确认和移动/复制选择器由 `apps/browser/useBrowserFileOperations.ts` 的单一待确认请求维护，操作类型、路径及存储一起冻结；页面仅从该请求派生显示状态，关闭统一清理，不同时保留两套弹窗上下文。三种写入共用忙状态，移动/复制仍先关闭选择器再提交，明确删除拒绝允许手动重试，已提交/未知错误限制当前确认的重复执行。收到逐项结果后释放忙状态并展示报告，再独立刷新目录；慢刷新不阻止新的确认交互，刷新错误不变成写入错误，也不会关闭后来打开的弹窗。卸载清除本地确认与报告，已发送写请求不取消，迟到结果不通知、清空选择或发起读取。不新增通用写操作框架、自动重发或跨重启回执。

仍有边界：上传批次票据已有跨重启结果索引，但部分管理操作回执尚未持久化，新建/密码修改不能仅靠列表证明；不能称为所有操作结果完整闭环。停用、收紧访问策略、中转模式切换及删除配置可先发布，不等待整项文件操作；旧执行者继续持有结算责任。更换连接或挂载路径仍最多等待 5 秒取得存储排他边界，重新启用也要拒绝未退出的旧执行者和待恢复记录；配置落盘及底层 I/O 不承诺固定耗时。单文件删除尚无跨重启持久结果回执；本次移动/目录/批量结果维护也不代表所有文件操作及所有外部修改组合已完成部署验收。

## 登录与权限

上传任务模型和网页操作资格集中在 `apps/browser/uploadQueue.ts`，按钮和队列处理共用纯规则，模块不依赖 Vue、API 或计时器。准备/排队/上传可以暂停，暂停可以继续；结果确认中仍属于活动任务，但不再次暂停/终止或清除。混合选择终止时只发送实际可终止成员的路径，不把已成功、失败或已终止任务一起送到取消接口；正在上传的终止仍先中断传输，再走原有结果核对。清除整个选择仍要求成员均已结束，未知失败禁止直接重试但允许移除网页记录；清除不调用文件删除接口，仅释放没有保留任务需要的旧票据，服务端结果和正式文件证据不变。卸载后的任务控制不再修改记录、请求或提示。

网页在当前已准备队列中最多运行四个文件执行者，一个文件传输结束即领取下一项，不等待其他文件完成。每个文件有独立取消句柄，暂停/终止只中断选中项，卸载取消所有在途传输；中断后的结果核对不占文件执行者，未知结果仍不重传。新加入的待准备项在当前波次结束后准备，不新增无限后台任务池。四文件并发与 S3 单文件四分片并发是两层限制，仍受服务器账号/存储准入和全局中转载荷预算约束。

上传弹窗共用任务模型中的字节归一、单文件进度和单次遍历摘要，计数与总进度从同一份任务派生，不保存第二份运行状态。失败、已终止和暂停的传输字节不当作已完成，只有全部任务确认成功才显示 100%；零字节文件和空队列单独处理，负值、超出文件大小和 NaN 的进度不会产生非法百分比。速度提示改为浏览器上传速率，不声称所有 S3 文件字节经过 Ycloud。此整理没有新增操作框架、依赖、持久格式，也没有改变服务端权限、额度、提交/清理规则或分片并发。

上传服务端状态解释集中在 `apps/browser/uploadTaskState.ts`：只更新任务展示及重试资格，使用已有中英文选择函数，不执行 API、计时器、通知或目录刷新。已确认完成优先于本地暂停/终止意图，临时清理未结束仍是成功；未知/执行中结果禁止直接重传，管理员关闭但提交未知的任务不能解释为确认未提交。`useUploadQueue.ts` 继续拥有取消、状态反馈及页面生命周期，成功和异常后的暂停/终止共用一个核对入口，有限结果查询由 `uploadReconciliation.ts` 管理。票据检查、准备和文件传输在异步等待后重新检查页面是否已卸载，迟到结果不通知、刷新、准备剩余批次或启动下一文件；迟到的准备票据仍通过原取消 API 释放，准备后的单项取消等待期间卸载也释放整张票据。不取消服务端已完成的正式文件，不新增通用任务状态机、持久后台队列或自动重传。已发送的状态查询仍有公共客户端截止时间；忽略迟到结果不意味着底层请求立即结束。

上传任务的存储分组和票据分组集中在 `apps/browser/uploadTaskGroups.ts`，只有任务模型的类型依赖，不执行请求或解释状态。准备、传输、取消、释放及页面卸载共用分组规则；票据身份包含存储 ID，保持首次分组和组内任务顺序。分组保存原任务引用，暂停/终止在请求等待期间的变化不会被副本覆盖；执行阶段仍重新检查任务状态与票据。批次状态和服务端编号响应在当前处理阶段分别建立一次路径索引，重复响应路径保留首次匹配，缺失编号沿用原路径；索引不跨请求缓存。分组、批量路径匹配和待释放票据检查改为线性遍历，未读取文件正文或改变传输并发。没有新增通用分组框架、持久格式或依赖。

`apps/browser/uploadReconciliation.ts` 管理上传结果读请求、批次成员和重试计时器；同一存储/票据同时只保留一条核对链、一个在途读取或一个定时器，所有待核对文件共用一次响应路径索引。每条链最多读取七次（首次加六次延迟重试），新成员加入活动链不重置预算；已经确定结果的文件退出，网络失败和缺失项继续有限核对，预算耗尽保留未确认且不重传。不同存储/票据隔离；任务被移除、已确定结果或更换票据时丢弃旧结果。队列用按成员变化失效的 computed Set 提供保留任务身份，不在每个文件查询时重新扫描全部队列。卸载清除计时器和批次成员，迟到读响应不更新任务或重新安排查询；没有永久响应缓存，后续独立核对链仍有自己的预算。

上传成功的目录刷新不再属于队列推进的等待条件，普通完成和核对成功共用队列内刷新入口。只保留一个在途刷新与一个合并后的待刷新目标，目标绑定请求时的存储/目录，执行前及错误反馈前重新核对当前页面；导航或卸载丢弃旧目标及旧错误。慢刷新或读取失败不阻止已经排队的文件，也不把上传成功改成失败；读取错误单独反馈，不重发上传。实际列表请求的取消及过期响应校验仍由 `useBrowserListing.ts` 负责，不新增通用读取框架。

上传的文件/目录输入收集在 `apps/browser/uploadCandidates.ts`，任务模型在 `uploadQueue.ts`，`useUploadQueue.ts` 负责任务准入、票据、传输和结果核对。输入收集最多 20,000 项，拖放目录及文件都计数，在去重前执行；保留任务的 20,000 项队列上限仍在准入时独立检查，后台单文件和批次限制不变。选择超限或任一读取失败整批不入队，不返回部分候选。目录使用迭代式深度优先遍历，逐块获取内容，每次只等待一个原生文件/目录回调，保持根条目、子项及分块的原顺序，不把整棵目录树展开成并发 Promise。该预算只限制应用收集的条目/候选，不限制浏览器已创建的 FileList、原生返回的单块大小或整体内存；不读取文件正文。拖入时先冻结存储及基础目录，再异步收集；之后切换目录/存储不会将旧文件上传到新位置。离开页面取消待收集输入的等待，迟到回调和错误不创建任务或提示；无法取消浏览器底层已经发起的文件回调。输入取消不改写现有服务器票据、上传提交/清理语义、文件传输顺序或 S3 分片并发。

文件浏览的请求取消、顺序检查和页面状态由 `apps/browser/useBrowserListing.ts` 维护；存储是否可选、是否应清除偏好，以及按身份隔离的浏览器偏好读写集中在 `storageSelection.ts`。临时健康异常不清除偏好，停用、权限撤销或存储移除才清除；浏览器本地存储不可用不阻止加载。列表结果共用一个状态应用入口，清空旧条目与权限共用一个重置入口，不引入额外状态机。只有当前请求可以应用结果或写入偏好，API 权限优先于旧版 `can_write` 兼容值；切换存储和重新登录仍先清空旧条目与权限，再等待新结果。

文件下载检查和打包准备在 `apps/browser/useBrowserDownloads.ts`，不依赖写操作弹窗、选中项或目录刷新；`useBrowserFileOperations.ts` 维护批量变更，新建与重命名由专用编辑模块维护。单文件下载按完整 URL 防止重复检查，打包准备共用忙状态，两者互不阻塞。请求冻结存储与路径，打包的限制提示也使用请求时的上限，不被后来切换存储覆盖。卸载后忽略迟到结果、禁止提示及跳转，不取消已经接受的打包准备；请求仍有公共客户端截止时间，不自动重复。服务器权限、打包限制、票据及流式归档规则不变。

新建文件夹和重命名的草稿、冻结请求上下文及生命周期在 `apps/browser/useBrowserEntryEditor.ts`，文件页共用一份短字段弹窗。具名操作区分新建目录和重命名目标，不建立通用 CRUD 框架；打开时检查相应能力，后台仍承担最终权限与名称校验。写入期间不替换或关闭编辑器，遮罩和取消按钮共用关闭规则；已提交/结果未知的错误复用 `ApiError.blocksRetry`，当前编辑器不直接重复确认。明确拒绝保留草稿，允许修正后手动重试。确认成功后关闭编辑、释放忙状态并提示，再独立刷新列表；刷新失败不写入编辑错误，也不重复正式操作。卸载清理本地编辑状态并忽略迟到结果，不取消已发送写请求，不启动离开页面后的刷新。此维护不新增跨重启回执或改变服务器事务证明。

文件页的图片导航、音频播放队列、文件弹窗目标及不支持格式的下载确认集中在 `apps/browser/useBrowserPreviews.ts`，页面保留播放器展开/收起、展示和下载执行。文件弹窗、回退下载和音频队列绑定打开时的条目快照及存储；同一存储的列表刷新不改写播放队列，切换存储同步清除预览交互。文件弹窗按存储/路径设置组件 key，避免替换文件时复用旧读取状态。音频错误检查复用现有有界 HEAD 接口，打开/关闭/切换/卸载使旧结果失效，不能因播放器已为空就重新打开旧下载确认；不新增轮询或自动下载。列表与画廊点击共用已有 `openEntry` 能力入口，缩略图及图片导航共用 `previewKind` 格式规则。预览关闭不取消其他写请求，此模块不承担文档内容读取、媒体控件或服务器权限校验。

文件弹窗与独立预览页的文本读取共用 `shared/api/textPreview.ts` 和 `shared/composables/useTextPreview.ts`：前者负责 Range 请求、有界正文读取和 HTTP 错误，后者只负责当前目标的状态与请求生命周期。读取包含正文消费的共享超时；更换目标、禁用预览或卸载会取消旧读请求，并忽略迟到成功/失败。请求前 2 MiB，即使存储忽略 Range，也只将最多 2 MiB 字节保留在预览缓冲中；通过 Content-Range 或额外正文确认截断，停止消费剩余正文。该限制不是浏览器整体内存或网络流量的硬上限。完整 HTML 仍使用原 sandbox/CSP，截断 HTML 只显示源码。下载错误不改写文本读取结果，不新增自动重试、探测或通用查询框架。

PDF/媒体预览的额度诊断由 `shared/composables/useMediaPreview.ts` 管理，文件弹窗、独立页和图片画廊共用；`usePreviewDownload.ts` 只负责这些预览界面的下载准入、重复点击保护和反馈。两个模块各自绑定包含文件和存储的完整 URL；目标替换、禁用和卸载时取消旧 HEAD，并在应用反馈/跳转前检查取消状态，同一目标往返也不接收旧结果。普通媒体只在加载失败后诊断一次，PDF 在显示前检查额度、显示后发生加载错误时可诊断一次；没有持续探测或自动重试。HEAD 接口保留共享超时和现有布尔诊断语义，无法诊断的网络错误不假报为额度用尽，也不证明文件可预览；实际 GET 和后端权限仍决定读取结果。预览下载换目标后不启动旧文件的下载，下载失败可手动重试；已开始的浏览器下载不由此取消。文件列表下载及归档准备仍由原 `useBrowserDownloads.ts` 维护，不因关闭预览取消后台写任务。图片画廊按完整源 URL 重置缩放/拖动，不只按路径判断存储变化。

音视频的 DOM 播放状态、进度/音量/循环同步和资源生命周期集中在 `shared/composables/useMediaPlayback.ts`；`MediaPlayer.vue` 保留布局、音量弹窗、全屏和上一首/下一首导航。两种媒体共用事件绑定和有界进度计算，不在模板内分别维护状态。源 URL 改变时替换媒体元素，旧元素在替换或卸载时解除监听、暂停、移除 src 并调用 load 停止旧源加载；该操作不承诺浏览器立刻回收全部内存。每个元素只允许一个在途 play 请求，迟到拒绝只可反馈到仍有效的目标，pause/load 引起的 AbortError 不假报文件损坏。自动播放按每个新元素尝试一次，被浏览器策略拒绝时保持可手动播放，不新增自动重试或额度探测。音量弹窗 ID 在同一应用内唯一，切换源/媒体类型关闭旧弹窗，Escape 关闭后归还焦点；视觉样式、文件权限和流量口径保持。

管理员密码/TOTP 改动只撤销管理员会话。普通用户额度变动不撤销登录；密码、用户名、启用状态或存储权限实际变化才撤销对应用户。服务器文件权限校验仍独立执行，不能因为浏览器显示旧界面而放行。

WebDAV 的挂载认证、持久失败限制及只读授权集中在 `webdav/access.rs`，协议分派和存储操作留在 `webdav.rs`。挂载仍要求独立的 Basic 凭据，不支持无密码公开 WebDAV；首次未带凭据的挑战不计失败，已带错误凭据才计入。只读挂载认证成功但拒绝写操作，不把权限拒绝记成密码错误。密码执行许可最多等待 3 秒，已开始的密码计算自行持有许可直至结束；DAV 保留独立请求准入门禁。

`webdav/credential_cache.rs` 仅保存已经通过现有 Argon2 验证的密码证明，最多 64 项，固定 5 分钟到期，命中不延长寿命；满时淘汰最早插入项，重启不保留。每个证明是进程内随机密钥生成的 HMAC-SHA256，绑定完整当前挂载配置和本次提交的密码，不保存明文密码、请求头或配置快照。每个请求仍读取当前挂载、检查启用状态、IP 封禁和只读权限并执行原登录记录规则；错误凭据不缓存，凭据、挂载路径、存储或权限改变后不匹配旧证明。缓存锁不跨密码计算、文件或账本 I/O，不新增数据库、配置字段或通用缓存框架。参考 [SFTPGo 的 WebDAV 认证缓存](https://github.com/sftpgo/docs/blob/main/docs/config-file.md#cache)，未照搬其无限期缓存设置。可用 `cargo test cached_webdav_authentication_baseline --locked -- --ignored --nocapture` 测量同机冷验证与热验证；这不是远端传输吞吐或手机兼容性验收。

WebDAV PUT 共用后台单文件大小上限（初始 5 GiB，受部署包络约束）、容量预留、全站流量额度和全局上传限速；本地支持已知或未知长度请求体，S3 PUT 仍要求有效 Content-Length。下载没有单独的文件大小上限，仍受全站流量额度、全局下载限速和后端传输许可约束；支持单段 Range，HEAD 不传输或计量文件正文。传输速率为 0 时不做应用层限速，两方向分别在所有相关传输之间共享，不是每任务独占速率。DAV 请求处理准入最多 8 项，PUT 持有至处理结束；GET 返回响应后释放 DAV 准入，正文继续持有后端流许可。本地写入默认共用 4 项 I/O 许可，每本地实例的下载流许可默认也是 4 项，不等于每个手机独享四任务。请求处理默认 300 秒，PUT 默认 6 小时；GET 的服务端处理超时只到响应建立，不是整个下载正文的时限。代理和客户端有各自的超时，不能仅凭客户端 Read timed out 判断文件未提交。网页四文件队列、自动编号和 S3 浏览器直传不用于 DAV；PUT 保持替换语义，不支持上传断点续写，未增加自动重试。

GET 和 HEAD 共用后端文件响应策略及范围读取；HEAD 保留文件头、去掉正文，不进入下载计量和限速包装。PUT、DELETE、MKCOL、MOVE、COPY 共用 `mutation_response`：已提交或结果未知的后端错误保留提交、清理和重试详情，不丢成单一状态码；普通协议错误仍按原状态码返回。Destination 只在 MOVE/COPY 内解析，仍限于同一主机及同一挂载。

## 状态、内存与流量

存储左侧绿色表示最近连接操作成功，红色表示连接检查失败/后端未准备。读取、传输和变更结果可更新缓存；非法路径、额度及用户权限错误不等价于存储断连。健康任务独立于清理任务，每 300 秒检查已缓存实例，单次最多 10 秒；管理存储页可见时每 300 秒读回状态，不在展示接口里高频探测。灯不是磁盘健康诊断或实时 SLA，停用另行标注；启动时未准备成功的实例需重新启用/编辑初始化。

后台概览在一次配置读锁下取得域名、限额、账户和存储配置，释放锁后再读取存储运行状态与本地挂载状态；响应中的配置字段来自同一快照，健康和用量是随后取得的运行时观察值，不表示整个响应具备跨存储的原子时刻。

新建 S3 存储默认由浏览器直传，最多 4 分片并发、基础 64 MiB；超大文件按分片数量限制自动增大分片。载荷不经过 VPS，实时速率表示浏览器发送速度，不证明对象存储已提交。每账号最多 4 个未结束上传批次、同时执行最多 4 个直传文件任务，不同登录会话共享限制；超出拒绝新任务，服务端不无限排队。

中转边接收边转发，不缓存完整分片，含小文件及 WebDAV 上传共用进程全局载荷字节预算：可检测内存上限的 1/32，限制在 4–32 MiB，检测失败默认 16 MiB。读取请求体前预留 1 MiB 窗口，预算满时停止读入并等待，最后一个数据引用释放后归还，异常和取消也会释放。直传不占此预算；它不是整个进程 RSS 硬上限，TLS/SDK/其他工作仍占内存。

Ycloud 统计/限制的是经过 VPS 的文件字节，不是物理网卡总流量。直连上传与下载不计入管理员、普通用户、访客及全站用量。仅修改额度不改变原重置时间戳或时区。

浏览器下载与预览共用存储权限、文件夹锁、后端读取及 VPS 流量计量/限速流程；两者只在附件下载与安全预览的响应策略上区分，不能让预览成为绕过下载权限或流量限制的旁路。

读取范围与版本条件统一由 `storage/read_conditions.rs` 决定。本地先在传输许可内打开文件，再从该句柄读取元数据和正文，避免路径替换后长度来自旧文件、正文来自新文件；这不保证外部程序原地修改已打开文件时的快照隔离。S3 元数据提供 ETag，正文 GET 继续以该 ETag 作 If-Match。HEAD 忽略 Range，仅返回完整文件元数据和空正文，S3 不再额外发送正文 GET。本地 HEAD 返回后即释放文件句柄与传输许可，原有权限及浏览器额度诊断保留。

`If-Range` 只接受唯一且与当前对象一致的强 ETag；不匹配、弱标签、无标签或日期条件均退回完整 200 响应，不把不同版本拼接为续传。日期无法在当前实现中证明强一致；本地只给出 Last-Modified，不把大小/时间当作强 ETag，也不每次下载扫描整文件。普通单段 Range 仍返回 206，无效范围返回 416。此读取路径不负责写入条件或账本格式，写入保护见下文；回归不证明手机上传超时已经解决。

WebDAV 的 XML 请求选择在 `webdav_xml/query.rs`，XML 响应留在 `webdav_xml.rs`，协议错误转换在 `webdav/error.rs`。PROPFIND 按 XML 命名空间解释 prop/propname/allprop/include：空正文为 allprop，重复属性按命名空间及名称去重，未知属性以独立 404 propstat 返回，不混入成功属性；propname 仅返回名称。现有五种可用属性保持，不伪造 getetag、创建时间或锁能力，未引入额外对象元数据探测。集合 href 带尾部斜线。DTD 实体不展开，也没有外部实体解析器；roxmltree 只启用 std，不自建 XML 解析器。

PROPFIND 控制正文仍最多 64 KiB，解析最多 2048 节点、128 个请求属性（去重前），命名空间最多 1024 字节、属性本地名称最多 256 字节；生成正文最多 8 MiB，超过时明确返回 503 并提示收窄查询，不返回截断的 207。此正文上限不是进程 RSS 上限，原目录条目上限仍单独生效。Depth 仅接受 0、1、infinity：非法/重复为 400；目录 infinity 或省略头为 403，返回 DAV:propfind-finite-depth，不静默降为一层。文件的 infinity 不导致目录递归。行为依据 [RFC 4918 §9.1](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1)。

MOVE/COPY 的绝对 Destination 采用解析后的 authority 比较主机和有效端口，接受主机大小写及省略默认 HTTP 80/HTTPS 443 的等价写法；不同主机/端口、查询串仍拒绝，目标继续限定同一挂载。相对目标保留原路径规则，路径百分号解码仍只做一次；此比较不用于推断实际 TLS 或信任反代。普通后端错误复用 AppError 的安全正文和现有能力错误码；内部上下文/来源不返回给客户端，已提交/未知操作证据及禁止重复执行规则保持。401 仍带 Basic challenge。无条件上传保留覆盖与提交规则，有条件写入按下述能力边界处理。

后台流量面板的额度编辑由 `apps/admin/useTrafficSettings.ts` 维护，图表与日期查询留在 `TrafficPanel.vue`。编辑快照只复制可修改的全站、访客、用户合计额度及重置周期，不读取账号独立额度。保存按具名字段比较并仅发送变更组，不使用 JSON 字符串顺序决定是否变更；未修改周期控件时保留原时间戳和时区。草稿与提交内容均独立于正在刷新的统计对象，保存中不重复请求；反馈、统计刷新及丢失响应后的安全回读仍沿用现有入口，没有新增任务机制或改变记账规则。

上传、下载共用有界流量批处理：只合并已经就绪的数据帧，累计到 256 KiB 或检查完 64 帧就停止，不等待凑满、不增加预读任务或整文件缓存。源数据帧可能超过该字节目标，整帧记账、不拆出未记账尾部；256 KiB 是停止追加的目标，不是上游单帧分配或整个进程内存的硬上限。批次先校验额度并持久记账，再按原字节片段向下游释放；取消 HTTP 等待者不会取消已经发出的记账写入，账本格式、损坏拒绝和重启重放保证不变。记账统计的是进入这一放行边界的文件字节，不是对端确认收到的字节；下游中断时不会撤回已放行批次的记录。可运行 `cargo test batched_frame_accounting_baseline --locked -- --ignored --nocapture` 对比同机小帧逐笔同步与合并同步耗时；这不是部署吞吐或 CPU 的验收结果。

本地下载以 256 KiB 为读取窗口，仍按 Range 限定范围并持有原有传输许可；本地上传把小写入合并到最多 256 KiB 的缓冲区，不缓存完整文件。尚在缓冲区或等待实际写完的字节继续占用物理空间预留，写入完成后才释放预留；尾部缓冲在正式发布前写完，最终文件同步、原子提交及操作收据仍是成功边界。中断未提交上传只清理本次暂存，不删除正式文件。完成阶段超过一秒时记录缓冲写入、文件同步、提交门禁等待、正式发布及容量结算的耗时；票据结果持久化超过一秒另行记录，用于区分 99% 之后的服务器等待，不把浏览器发送完毕当作上传成功。

`traffic/commit.rs` 的单个执行者拥有账本文件，待处理通道最多 64 项，每次仅合并已到达的最多 64 条记录，一次追加与同步，不等计时器凑批。按顺序在候选账本上检查累计额度，磁盘成功后才发布确认账本并放行各流；被拒绝项不写记录。公开账本锁不跨磁盘 I/O，统计读取和配置编辑不等待同步。请求进入通道后即由执行者结算，不因 HTTP 等待者消失丢弃；入队前的背压等待可以取消。写盘失败停止后续计量放行，保留原账本供恢复，不清零；日志序号、重启重放及压缩规则保持。WebDAV 与网页共用此链路，没有改成成功后才补记或定时丢失窗口。

`transfer_limit.rs` 的在途上传与下载始终保留同一限速适配器，在线从 0 改为有限速率后，后续尚未消费的数据帧按新速率放行；从有限速率改为 0 会唤醒当前等待者。改变速率会通知所有等待者重新核对共享令牌桶，不持锁睡眠、不预留无法取消的令牌债务。0 路径只检查当前速率，不获取令牌桶锁；已放行帧不能追回，所有流仍共享同一方向的桶，流量额度与此无关。配置变化不是任意时刻收回已写入网络的数据，也不保证各并发流严格公平。

S3 上传/分片日志和目录事务日志共用 `s3_backend/journal.rs::write_encoded_journal`：只接收已经编码的字节，集中处理 provider 条件头、请求许可、恢复登记、远程 PUT 和返回 ETag 校验。调用方仍负责各自的认证、schema 校验及清单字节上限，现有磁盘/对象记录格式不变。标准 S3 的新建 If-None-Match 与更新 If-Match 保持；OSS 保留原有禁覆盖头和更新前版本检查，该兼容分支不是对外部写入者的原子 CAS，不扩大单写实例保证。

生产浏览器上传仍经操作绑定收据入口；未绑定操作 ID 的 `StorageBackend::upload_new_file` 以及不带预期大小的 `S3Backend::copy_directory` 仅作为测试夹具编译，不保留为运行时候选入口。现有网页调用的存储准备/激活/丢弃接口及历史迁移未删除。浏览器直传进度按单分片累计值的差量更新总量，重复的最终进度事件不重复计数；四分片并发、取消结算及服务端提交核验不变。

大型目录快照排序在现有构建许可内交给阻塞线程，不占异步请求线程；每实例原有两项构建预算、缓存失效及分页规则保持，不并行执行具有目标冲突的目录变更。

2026-09-27 Windows 本机 debug 历史基线：1024 次 64 KiB 持久记账耗时约 632 ms，纯记账吞吐约 101 MiB/s。它早于上述有界合并提交改造，不代表当前端到端上传或 NAS/VPS 磁盘性能。单元回归通过不证明真实部署的 99% 等待或 CPU 已解决；仍需使用新镜像区分反代传输、Ycloud 完成日志和磁盘同步耗时。

## WebDAV 条件写入边界

条件解析与判断统一在 `storage/write_conditions.rs`，不在页面或 handler 维护另一套判断。PUT 接收 If-Match/If-None-Match 和 If-Unmodified-Since；标签清单最多 4096 字节、32 项，引号内逗号不是分隔符。If-Match 使用强比较，If-None-Match 使用弱比较；If-Match 存在时忽略日期，非法日期按 HTTP 规则忽略，重复日期拒绝。规则依据 [RFC 9110 §13.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.2.2)。这是有限能力实现，不是完整 WebDAV 条件/锁支持声明。

| 场景 | 实际规则 |
| --- | --- |
| 本地 PUT 的 If-Match: * / If-None-Match: * | 检查存在/不存在；接收前检查，原子提交持有 mutation_gate 后再次检查，失败 412。 |
| 本地 PUT 的修改时间条件 | 使用文件实际修改时间的秒级比较；没有 If-Match 时才生效。不能检测同一秒内的所有变化，也不防止绕过 Ycloud 的外部写入。 |
| 本地 PUT 的具体标签 | 当前不生成强 ETag，具体 If-Match 不会匹配，返回 412；已有文件的具体 If-None-Match 无法核验时返回能力错误，不猜测后覆盖。 |
| 非 OSS 的 S3 条件 PUT | 限单对象原子复制范围（最多 4 GiB），需要返回 ETag 并通过条件能力核验。再次读取目标后把该决策版本固定到正式 CopyObject 的 If-Match 或 If-None-Match。 |
| S3 的单独修改时间条件、OSS 条件 PUT、超出上述范围的条件 PUT | 正式请求前明确拒绝；If-Match 已覆盖的日期不单独执行。普通无条件上传不因此被禁止。 |
| DELETE/MKCOL/MOVE/COPY 等其他写方法的有效条件，以及 DAV If 锁条件 | 返回 501，不忽略条件执行文件变更；无条件方法沿用原实现。 |

本地条件在 `ReplacementObserver::check_destination` 核验，位于事务所有权转移、日志和改名前；失败只清理本次暂存，不改正式文件、不提交逻辑容量。原收据、原子替换与空间预留语义保持，没有整文件散列或新的本地版本数据库。明确失败使用稳定 `precondition_failed` / HTTP 412，内部错误仍按共享错误协议处理。

S3 条件发布由 `conditional_publish.rs` 协调。首次使用时，在已登记上传事务所拥有的私有备份键放置空对象，验证后端拒绝不匹配版本和已有对象上的禁止覆盖请求；不复制文件载荷、不修改桶规则或正式文件。成功结果仅缓存在当前客户端实例，重启或更换连接后重新核验，元数据编辑复用实例。条件上传不建立旧正式文件的备份，也不采用失败后恢复备份的分支；正式复制只发送一次，禁用该请求的 SDK 自动重试，避免第一次成功而重试 412 被误报为未提交。

有条件上传的认证日志采用 v2，绑定发布条件及 CheckingPublication / PublicationStarted / PublicationRejected 阶段。检查阶段证明正式发布尚未开始；明确拒绝阶段证明本次正式请求未提交，恢复只清理同 ID、正确操作标记与大小的私有对象。开始阶段仅凭当前正式对象的本次操作标记及大小确认成功，不凭暂存 ETag、旧文件仍在或目标不存在猜测失败；无法证明时保留日志和资源，绝不恢复旧文件或重新发送正式复制。日志发布与实际发出请求之间的极短崩溃窗口也可能保守保持未知，不能声称全部未知均能自动结清。拒绝日志写入先返回，随后临时清理最多等待共享的 500 ms，未清理完保留恢复责任；清理期限不强行中断已发阶段日志写入。

普通无条件上传继续使用 v1 日志，省略新字段；现有 v1 记录可读，Multipart v1/v2 格式不变。不要在仍有 v2 条件事务时降级到旧二进制；旧代码不会认识新阶段/字段。这里不新增 WebDAV 统一跨重启结果回执，也不扩大已有上传票据的查询范围。尚未完成真实 S3、Linux 断电及手机弱网验收，协议回归不等于已定位手机 400 或上传超时。
