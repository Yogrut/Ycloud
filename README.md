# Ycloud

Ycloud 是一个使用 Rust、Axum 和原生 HTML/CSS/JavaScript 构建的轻量级私有文件服务。它将网页文件管理、目录访问控制和 WebDAV 挂载整合在一个可执行程序中，适合个人设备、家庭服务器和可信局域网内的小规模文件共享。

项目以三个目标的平衡为长期原则：

> 稳定、安全、高性能；不以明显牺牲另外两项为代价追求单项极致。

Ycloud 不是完整的企业网盘，也不打算用复杂的功能数量换取表面上的“全能”。当前版本更关注清晰的权限边界、可预测的文件操作和较低的运行维护成本。

## 核心功能

- 响应式网页文件浏览器，支持明暗主题与当前目录搜索。
- 上传、新建目录、单文件下载、多选打包下载、重命名、删除、移动和复制。
- 图片、视频、音频、PDF、文本与 Markdown 等常见文件预览。
- 独立的管理员账号、网页访问密码和网页文件夹锁。
- 多个 WebDAV 挂载，每个挂载可设置独立路径、账号、密码和只读权限。
- 大文件流式上传与下载、单区间 HTTP Range 请求；中文下载文件名使用标准 UTF-8 响应头。
- 原子上传、配置备份恢复、请求超时、并发限制和优雅关闭。
- 无前端构建链：静态页面编译进程序，运行时不需要 Node.js。

## 适用与不适用场景

适合：

- 在个人电脑、NAS 或家庭服务器上管理文件。
- 在可信局域网中向手机、平板或桌面 WebDAV 客户端提供存储。
- 希望使用单个 Rust 服务、避免部署数据库和独立前端服务。
- 需要少量明确账号边界，而不是复杂组织和协作权限。

暂不适合：

- 多租户、团队协作、审计合规或细粒度 RBAC 场景。
- 需要文件版本历史、回收站、增量同步或服务端全文检索的场景。
- 需要 WebDAV Class 2 锁、集群部署或多实例同时写配置的场景。
- 不经过 HTTPS 反向代理就直接暴露到公网。

## 快速开始

### 环境要求

- 稳定版 Rust 工具链（建议通过 [rustup](https://rustup.rs/) 安装）。
- Windows、Linux 或 macOS。
- 无需 Node.js、数据库或外部静态资源服务。

### 获取并启动

```bash
git clone https://github.com/YogruTi/Ycloud.git
cd Ycloud
cargo run --release --locked
```

首次启动会创建 `storage` 和 `config.json`，生成随机管理员密码并输出到终端。服务默认监听 `0.0.0.0:3000`，允许本机和网络可达设备连接。

打开 `http://127.0.0.1:3000`，使用终端输出的初始凭据登录后台，并立即更换管理员密码。停止服务时按 `Ctrl+C`，程序会等待正在处理的请求结束。

### 默认值

| 项目 | 默认值 |
|---|---:|
| 监听地址 | `0.0.0.0:3000` |
| 文件目录 | `./storage` |
| 配置文件 | `./config.json` |
| 单文件上传上限 | 5 GiB |
| 单文件下载上限 | 不限制，使用流式传输和 HTTP Range |
| 打包下载上限 | 展开后原始总大小 3 GiB、最多 1,000 个文件 |
| I/O 并发上限 | 4 |
| 同时打包下载 | 1 个 |
| 单次目录列表上限 | 10,000 项 |
| 请求超时 | 300 秒 |
| 上传超时 | 6 小时 |
| 磁盘安全余量 | 512 MiB |
| Secure Cookie | 关闭 |

默认监听所有网卡是为了让局域网 WebDAV 可以直接连接。只在本机使用时，建议将 `BIND_ADDRESS` 设置为 `127.0.0.1`。

## 配置

服务级配置通过环境变量提供，账号、网页密码、文件夹锁和 WebDAV 挂载保存在运行时配置文件中。

| 环境变量 | 说明 | 默认值 |
|---|---|---:|
| `BIND_ADDRESS` | 监听 IP | `0.0.0.0` |
| `PORT` | HTTP 端口 | `3000` |
| `STORAGE_PATH` | 文件存储路径 | `./storage` |
| `CONFIG_PATH` | 运行配置路径 | `./config.json` |
| `MAX_UPLOAD_BYTES` | 单文件上传字节上限 | `5368709120` |
| `IO_CONCURRENCY` | 流式文件 I/O 并发上限 | `4` |
| `MAX_LIST_ENTRIES` | 单次目录列表上限 | `10000` |
| `REQUEST_TIMEOUT_SECS` | 请求超时秒数 | `300` |
| `UPLOAD_TIMEOUT_SECS` | 网页上传和 WebDAV PUT 的超时秒数 | `21600` |
| `DISK_RESERVE_BYTES` | 上传后必须保留的磁盘可用空间 | `536870912` |
| `SECURE_COOKIES` | Cookie 是否仅通过 HTTPS 发送 | `false` |

PowerShell 示例：

```powershell
$env:BIND_ADDRESS = "127.0.0.1"
$env:PORT = "3000"
$env:STORAGE_PATH = ".\storage"
$env:CONFIG_PATH = ".\config.json"
cargo run --release --locked
```

Bash 示例：

```bash
BIND_ADDRESS=127.0.0.1 PORT=3000 cargo run --release --locked
```

`config.example.json` 仅用于展示当前配置结构。不要将真实的 `config.json`、`config.json.bak` 或 `storage` 内容提交到 Git。

## WebDAV

在管理后台创建并启用挂载后，客户端地址格式为：

```text
http://服务器地址:3000/dav/挂载名称/
```

WebDAV 使用每个挂载自己设置的用户名和密码，不使用管理员密码，也不使用网页访问密码。当前实现支持 WebDAV Class 1 常用方法：

- `OPTIONS`
- `PROPFIND`
- `GET` / `HEAD`
- `PUT`
- `DELETE`
- `MKCOL`
- `MOVE`
- `COPY`

当前未实现 `LOCK`、`UNLOCK` 和 `PROPPATCH`，也不会在 MOVE/COPY 时隐式覆盖已存在的目标。依赖完整 Class 2 行为的客户端可能无法正常工作。

## 安全模型

Ycloud 将四种权限明确分离：

| 通道 | 凭据 | 作用范围 |
|---|---|---|
| 管理后台 | 管理员用户名和密码 | 账号及服务配置 |
| 网页文件入口 | 网页访问密码或管理员会话 | 整个网页文件空间 |
| 网页文件夹锁 | 对应目录的锁密码 | 该目录及子目录的网页访问 |
| WebDAV | 挂载自己的用户名和密码 | 该挂载指定的路径 |

主要安全措施包括：

- 密码使用 Argon2 加盐哈希保存，管理 API 不返回密码哈希。
- 会话 Cookie 使用 `HttpOnly` 和 `SameSite=Strict`。
- 修改请求执行同源检查，网页启用严格内容安全策略。
- 文件路径规范化后再访问磁盘，阻止父目录跳转和存储根目录逃逸。
- WebDAV 不允许匿名访问；启用的挂载必须具备完整凭据。
- 上传先写临时文件，完成后原子提交，降低中断造成损坏的概率。
- 多文件由网页逐个请求上传，每个文件独立报告结果；单个失败不会中断后续文件。
- 上传面板根据浏览器真实传输事件显示总进度、当前文件、已传容量、平均速度和成功/失败数量。
- 多文件上传时，每个文件都有独立状态行；成功一个便立即刷新文件列表，失败项显示其具体原因，避免队列结束前看起来只上传了一个文件。
- 上传前检查实际可用磁盘空间，并为并发上传预留容量；上传结束后仍保留配置的安全余量。

### 公网部署

程序本身不终止 TLS。公网使用必须放在可信的 HTTPS 反向代理后，并设置：

```text
SECURE_COOKIES=true
```

同时应限制防火墙、及时更新依赖并备份 `storage` 与 `config.json`。不要把明文 HTTP 直接暴露到互联网；WebDAV Basic 认证只有在 HTTPS 下才具备可接受的传输保护。

## 项目结构

```text
Ycloud/
├── src/
│   ├── main.rs          # 程序入口
│   ├── bootstrap.rs     # 启动、监听、清理任务与优雅关闭
│   ├── app.rs           # 路由、中间件、限制和嵌入式静态资源
│   ├── auth.rs          # 登录、会话、访问令牌和密码计算
│   ├── security.rs      # Cookie、同源校验和安全响应头
│   ├── state.rs         # 共享状态和配置更新事务
│   ├── config.rs        # 配置模型、迁移、校验、保存和恢复
│   ├── storage.rs       # 安全路径、流式 I/O 和原子文件操作
│   ├── archive.rs       # 打包预检、一次性票据和流式 ZIP 输出
│   ├── file_access.rs   # 网页文件授权和文件夹锁判断
│   ├── api.rs           # 单文件网页 API
│   ├── batch_api.rs     # 批量删除、移动和复制
│   ├── admin_api.rs     # 账号、文件夹锁和 WebDAV 配置
│   ├── webdav.rs        # WebDAV 方法与 Basic 认证
│   ├── webdav_path.rs   # WebDAV 路径和 Destination 处理
│   ├── webdav_xml.rs    # PROPFIND XML 响应
│   └── error.rs         # 统一错误和 HTTP 响应
├── static/              # 无构建步骤的网页、样式和脚本
├── storage/             # 默认运行时文件目录（内容不进入 Git）
├── config.example.json  # 配置结构示例
├── ARCHITECTURE.md      # 当前版本的详细设计与边界
└── THIRD_PARTY_NOTICES.md
```

更细的模块职责、路径规则和认证边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 设计优势

- **部署简单**：一个 Rust 服务即可提供网页和 WebDAV，不依赖数据库与 Node.js。
- **故障边界清晰**：认证通道互相独立，网页文件夹锁不会意外改变 WebDAV 权限。
- **文件操作稳健**：流式 I/O、原子上传、配置串行写入和有效配置备份减少半成品状态。
- **资源使用可控**：上传大小、目录条目、I/O 并发和请求时间均有明确上限。
- **下载边界合理**：单文件下载不设大小上限；打包下载以 3 GiB 和 1,000 个文件双重限制控制遍历、元数据和持续 I/O 开销。
- **适配轻量服务器**：默认按 1 vCPU、1 GiB 内存设计；最多同时执行一个打包流和一个打包预检，密码哈希并发为 1，避免突发任务争抢 CPU 与内存。
- **攻击面较小**：静态资源本地嵌入，不加载外部脚本；路径、Cookie 和修改请求有专门防护。
- **维护成本低**：后端按职责拆分，前端共享主题系统，项目结构与运行数据分离。

## 已知缺点与边界

- 没有内置 HTTPS，安全公网部署需要额外的反向代理。
- 管理员会话、网页授权和文件夹解锁令牌保存在内存中，服务重启后需要重新登录或解锁。
- 运行配置采用单个 JSON 文件，适合单实例；多个实例不能同时写同一份配置。
- WebDAV 仅实现常用 Class 1 子集，部分强依赖锁协议的客户端不兼容。
- 当前没有数据库、用户系统、权限组、审计日志、文件历史或回收站。
- 当前没有浏览器端分块、暂停续传或断点续传上传；网络中断后需要重新上传当前文件。
- 当前目录搜索只过滤已经加载的目录，不递归扫描整个存储空间。
- 单选文件显示普通下载且不限制文件大小；多选项目统一打包下载，展开后必须同时不超过 3 GiB 和 1,000 个文件。
- 超过 `MAX_LIST_ENTRIES` 的目录会被截断，而不是分页返回。
- 文本与 Markdown 预览以安全纯文本方式显示，不渲染其中的活动内容。
- 项目目前没有自动发布安装包或容器镜像，使用者需要从源码构建。

这些限制是当前版本的真实边界。若需求包含企业协作、跨地域高可用或海量元数据检索，应优先选择更完整的存储平台，而不是强行扩展 Ycloud。

## 常见问题

| 现象 | 可能原因与处理方式 |
|---|---|
| 手机或其他电脑无法打开网页 | 确认使用服务器的局域网 IPv4 地址而不是 `127.0.0.1`；检查系统防火墙是否允许 TCP 3000；确认设备处于同一可互访网络。 |
| 启动时提示 `SECURE_COOKIES is disabled` | 服务监听地址不止本机，但 Cookie 尚未限制为 HTTPS。这在可信局域网调试时是风险提示；公网部署必须配置 HTTPS 并启用 `SECURE_COOKIES=true`。 |
| WebDAV 返回 `401 Unauthorized` | 使用了管理员或网页密码、挂载未启用、用户名/密码不匹配，或客户端保存了旧凭据。使用该挂载独立的用户名和密码并删除客户端缓存后重试。 |
| WebDAV 地址存在但找不到文件 | 检查 URL 是否包含 `/dav/挂载名称/`，并确认后台配置的挂载路径指向预期目录。 |
| WebDAV 客户端提示不支持锁 | 客户端依赖 Class 2 的 `LOCK`/`UNLOCK`；当前版本不支持，应关闭客户端锁要求或更换兼容 Class 1 的客户端。 |
| 进入加锁目录后再次要求密码 | 文件夹解锁令牌保存在内存并有有效期；服务重启、浏览器清理 Cookie 或令牌过期后需要重新解锁。 |
| 目录文件显示不完整 | 目录条目达到 `MAX_LIST_ENTRIES` 上限。确认目录规模，或在评估内存占用后提高该值。 |
| 大文件上传失败 | 检查 `MAX_UPLOAD_BYTES`、反向代理请求体限制、磁盘剩余空间、`DISK_RESERVE_BYTES` 和 `UPLOAD_TIMEOUT_SECS`。网页会逐个上传多选文件，不要求所有文件总和小于 3 GiB。 |
| `config.json` 损坏 | 程序会尝试使用最后一份有效备份恢复；仍无法启动时，先备份现有文件，再根据终端错误和 `config.example.json` 修复，避免直接删除存储目录。 |
| 忘记管理员密码 | 密码不可逆恢复。需要在停止服务并备份配置后执行受控的配置重建；不要直接手工填写明文密码到哈希字段。 |

## 开发与质量检查

```bash
cargo fmt --all -- --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo audit
cargo deny --locked check
cargo build --release --locked
```

提交代码前请至少运行格式、测试、Clippy 和依赖安全检查。修改认证、路径或文件写入逻辑时，应同时补充对应的回归测试。`cargo audit` 与 `cargo deny` 是开发审计工具，不属于 Ycloud 的运行依赖。
